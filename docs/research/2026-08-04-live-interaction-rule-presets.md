# 直播互动数值规则“小白模式”预制动作调研

- 调研时间：2026-08-04
- 调研目标：确定哪些“收到事件后改变一个数值”的操作值得加入本项目礼物规则小白模式。
- 来源范围：仅采用已经取得的 5 个官方文档或官方 Wiki 页面；不使用社区教程和二手文章，也不继续扩展工具范围。

## 结论

小白模式第一层建议固定为 6 个动作：

1. **增加**
2. **减少**
3. **设为**
4. **清零**
5. **按价格增加**
6. **按价格减少**

当前已有“增加、按价格增加、设为、随机增加、高级规则”，所以最应该立即补齐的是：**减少、清零、按价格减少**。[当前规则编辑源码][repo-current-ui]

另外增加两个可选安全限制，但不要把它们做成更多下拉项：

- **最低不低于**：`MAX(原公式, 最低值)`
- **最高不超过**：`MIN(原公式, 最高值)`

百分比、倍数、随机、条件分支等能力可以保留，但不放在默认小白列表；原因是本项目会把多个礼物逐个执行，容易产生复利、多次随机或中途切换条件。

## 1. 本项目的固定语义

本文用 `V` 表示当前属性名，例如 `加班时间`；生成正式规则时替换成真实属性名。

后端收到数量为 `N` 的礼物后，会循环执行规则 `N` 次。每次执行都会立即写回属性值，下一次使用更新后的值继续计算。[后台逐个礼物执行][repo-gift-loop]

公式中的：

- `price` 是单个礼物的价格；
- `price/1000` 对应当前 UI 中的“每 1 元”；
- 不需要也不应恢复 `count` 变量；
- 正式数据计算继续全部由后端完成。

后端已经支持 `+ - * /`、比较运算，以及 `IF`、`MAX`、`MIN`、`ROUND`、`ABS`、`RAND`、`RANDBETWEEN`。[后端公式引擎][repo-formula]

## 2. 五个一手来源给出的共同模式

| 一手来源 | 官方提供的相关能力 | 对本项目的启示 |
| --- | --- | --- |
| [Streamer.bot：Set Global Variable][streamer-global-set] | 把基础操作明确分为 `Value`、`Increment`、`Decrement` | “设为、增加、减少”应是第一层语义动作，而不是让小白写公式 |
| [Mix It Up：Counter Action][mixitup-counter] | Counter 提供 `Update`、`Set`、`Reset` | “清零”值得做成独立无输入动作，不能只藏在“设为 0”里 |
| [Mix It Up：Consumable Action][mixitup-consumable] | 用户货币、等级和库存都明确区分 Add 与 Subtract，并允许高级数学表达式 | “增加 / 减少”应成对出现；公式输入应留在高级层 |
| [Mix It Up：Goal Widget][mixitup-goal] | 事件贡献分为固定累加和“事件金额 × 配置倍率” | 本项目的“增加”和“按价格增加”是合理基础项，也应补齐价格减少 |
| [SAMMI：变量运算符与复杂数学][sammi-operators] | 支持赋值、加减乘除、取模、条件和复杂数学 | 完整数学能力适合高级模式，不应把所有运算符直接塞进小白下拉框 |

同类工具最稳定的基础集合不是“尽可能多的数学函数”，而是：**赋值、增、减、重置**。涉及金额的工具再增加“按事件金额计算”的入口。

## 3. 可立即实现的基础操作

### 3.1 第一层动作

| 中文短标签 | 小白模式一句话句式 | 公式映射 | 状态 |
| --- | --- | --- | --- |
| **增加** | 每收到 1 个「礼物」，让「V」增加 `[a]` | `V+a` | 保留 |
| **减少** | 每收到 1 个「礼物」，让「V」减少 `[a]` | 默认 `MAX(V-a,0)` | **新增** |
| **设为** | 每收到 1 个「礼物」，把「V」设为 `[x]` | `x` | 保留 |
| **清零** | 每收到 1 个「礼物」，把「V」清零 | `0` | **新增** |
| **按价格增加** | 每收到 1 个「礼物」，每 1 元让「V」增加 `[a]` | `V+price/1000*a` | 保留并统一名称 |
| **按价格减少** | 每收到 1 个「礼物」，每 1 元让「V」减少 `[a]` | 默认 `MAX(V-price/1000*a,0)` | **新增** |

这 6 项分别覆盖同类工具的一等操作：Value / Set、Increment / Add、Decrement / Subtract、Reset，以及按事件金额累加。[Streamer.bot][streamer-global-set] [Mix It Up Counter][mixitup-counter] [Mix It Up Consumable][mixitup-consumable] [Mix It Up Goal][mixitup-goal]

### 3.2 安全限制

安全限制放在动作句式下方，用复选框和数字输入，而不是继续增加动作名称。

| 短标签 | UI 说明 | 公式包装 |
| --- | --- | --- |
| **最低不低于** | 计算结果低于 `[L]` 时停在 `[L]` | `MAX(原公式,L)` |
| **最高不超过** | 计算结果高于 `[U]` 时停在 `[U]` | `MIN(原公式,U)` |

推荐默认值：

- “减少”和“按价格减少”默认启用 `最低不低于 0`；
- “增加”和“按价格增加”可选 `最高不超过`，默认关闭；
- 同时设置两项时生成 `MIN(MAX(原公式,L),U)`；
- 小白界面只显示自然语言，高级预览再显示 `MIN` / `MAX`。

Mix It Up 官方 Consumable 文档允许在高级计算中使用最小值函数，这说明边界控制适合作为基础动作的保护层，而不必成为一个新的主动作。[Mix It Up Consumable][mixitup-consumable]

## 4. 不放入默认小白模式的高级项

| 能力 | 可映射公式 | 不放第一层的原因 |
| --- | --- | --- |
| 随机增加 / 减少 | `V+RANDBETWEEN(a,b)`、`MAX(V-RANDBETWEEN(a,b),0)` | N 个礼物会随机 N 次；可以保留在“更多玩法” |
| 增加 / 减少百分比 | `V*(1+p/100)`、`V*(1-p/100)` | N 个礼物会逐次复利，不等于一次变化 `N×p%` |
| 变为倍数 / 除以数值 | `V*m`、`V/d` | 多次触发会形成乘方效果，并有除零风险 |
| 条件分支 | `IF(条件,结果A,结果B)` | 每次都用更新后的 V 重判，同一批礼物可能中途换分支 |
| 取整 / 绝对值 | `ROUND(...)`、`ABS(...)` | 属于结果修饰器，不是直观的事件动作 |
| 跨属性引用 | `属性A+属性B` | 会产生隐藏依赖和执行顺序问题 |
| `count` 或整批只算一次 | 需要改变执行模型 | 与“每个礼物按单个重复触发”冲突 |

SAMMI 的官方运算符表证明这些能力在通用自动化工具中确实有用，但它们属于完整数学能力，而非面向小白的最小操作集。[SAMMI 变量运算符][sammi-operators]

## 5. 推荐 UI

下拉框建议直接分组：

```text
常用
  增加
  减少
  设为
  清零
  按价格增加
  按价格减少

更多玩法
  随机增加
  随机减少

高级
  使用高级规则
```

选中动作后生成完整句子，例如：

```text
每收到 1 个「人气票」，让「加班时间」增加 [60] 秒
[✓] 最高不超过 [3600] 秒
```

预览至少同时显示：

1. 单个礼物：`0 → 60`；
2. 多个礼物：`3 个会执行 3 次：0 → 60 → 120 → 180`；
3. 折叠的生成公式：`加班时间+60`。

前端只负责组装句式、生成公式和展示后端预览；保存及正式触发后的数值计算仍由后端完成。

## 6. 实施顺序

1. 新增 **减少、清零、按价格减少**。
2. 为减少类动作默认加入 **最低不低于 0**。
3. 为增加类动作加入可选的 **最高不超过**。
4. 将现有“随机增加”移到“更多玩法”，同时补充“随机减少”。
5. 加入“多个礼物会逐个执行”的数量预览。
6. 百分比、倍数和条件暂不加入默认小白模式。

最终 P0 方案：

> **增加 / 减少 / 设为 / 清零 / 按价格增加 / 按价格减少**<br>
> 安全限制：**最低不低于 / 最高不超过**
