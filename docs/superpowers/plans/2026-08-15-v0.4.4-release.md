# v0.4.4 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the exact committed `master` as signed GitHub Release `v0.4.4` with matching update metadata and changelog assets.

**Architecture:** Prepare one narrowly scoped version/changelog commit, verify that exact commit locally, then push `master` and an immutable annotated tag. The existing tag-triggered GitHub Actions workflow owns Windows signing, provenance, update-manifest publication, and GitHub Release assets.

**Tech Stack:** Git, npm/Vitest/TypeScript/Vite, Go, GitHub Actions, GitHub CLI.

## Global Constraints

- Release version is exactly `0.4.4`; release tag is exactly `v0.4.4`.
- Existing uncommitted files in `E:\bilibili` remain unstaged and unmodified.
- Do not force-push, move an existing tag, upload an unsigned local EXE, or bypass the protected release workflow.
- The bundled changelog contains exactly one `0.4.4` fallback release dated `2026-08-15`.
- Push `master` before creating and pushing the release tag.
- Stop before any external publication if a local gate fails.

### Task 3: Push, tag, and verify the protected release

**Files:**
- External mutation: `origin/master`
- External mutation: Git tag `v0.4.4`
- External mutation: GitHub Actions release run and GitHub Release assets

**Interfaces:**
- Consumes: the verified Task 1 release commit SHA and `.github/workflows/release.yml`.
- Produces: published GitHub Release `v0.4.4` and its signed/update assets.

- [ ] **Step 1: Reconfirm remote and tag preconditions**

Run:

```powershell
git fetch origin master --tags
git rev-list --left-right --count master...origin/master
git tag --list v0.4.4
gh auth status
```

Expected: no unexpected remote divergence; `v0.4.4` does not exist; GitHub authentication is valid. If remote advanced, stop and integrate without force-pushing.

- [ ] **Step 2: Push the verified master**

Run:

```powershell
git push origin master
```

Expected: non-force push succeeds and `origin/master` resolves to the verified release commit.

- [ ] **Step 3: Create and push the immutable annotated tag**

Run:

```powershell
git tag -a v0.4.4 -m "release: v0.4.4"
git push origin refs/tags/v0.4.4
```

Expected: tag push succeeds and starts the `Release Windows executable` workflow.

- [ ] **Step 4: Monitor the release workflow**

Resolve the run for tag `v0.4.4` and watch it:

```powershell
$runs = gh run list --workflow release.yml --event push --limit 10 --json databaseId,headBranch,headSha,status,conclusion | ConvertFrom-Json
$releaseRun = $runs | Where-Object { $_.headBranch -eq 'v0.4.4' } | Select-Object -First 1
if (-not $releaseRun) { throw 'v0.4.4 release workflow run was not found' }
gh run watch $releaseRun.databaseId --exit-status
```

Expected: every build, test, signing, attestation, update-publication, and release step succeeds. On failure, inspect the resolved `$releaseRun.databaseId` with `gh run view $releaseRun.databaseId --log-failed` and do not move the tag.

- [ ] **Step 5: Verify published release assets**

Run:

```powershell
gh release view v0.4.4 --json tagName,isDraft,isPrerelease,publishedAt,assets,url
gh release download v0.4.4 --dir "$env:TEMP\gift-panel-v0.4.4-verify"
```

Expected: published, non-draft, non-prerelease release containing at least:

```text
gift-panel-windows-x64.exe
gift-panel-windows-x64.exe.sha256
gift-panel-update.json
gift-panel-changelog.json
```

Verify the downloaded EXE against the checksum and confirm the update/changelog JSON versions equal `0.4.4`. Record the Release URL and signed artifact checksum in the final handoff.
