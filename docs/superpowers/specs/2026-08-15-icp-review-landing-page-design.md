# 备案审核首页设计

日期：2026-08-15

## 目标

在上海轻量应用服务器上部署一个与当前备案变更信息一致的公开静态首页，保证 `bilibililive.cn`、`www.bilibililive.cn` 和 `app.bilibililive.cn` 在备案审核期间能够正常访问。页面如实介绍当前可用的本地开源版，并说明受邀网页版仍在建设中。

## 范围

本阶段只部署静态 HTML/CSS 页面和 Nginx 健康检查，不部署登录、邀请码、数据库、B 站连接或现有本地 Go 服务。页面不收集个人信息，不添加统计、广告、在线表单、评论、论坛、交易、新闻资讯、网络直播或音视频上传功能。

## 品牌与备案一致性

- 页面品牌名：`礼物互动工坊`
- 浏览器标题：`礼物互动工坊｜直播互动工具应用`
- 备案服务名称：`直播互动工具应用`
- 页面标题完整包含备案服务名称。
- 页面说明这是个人维护的非营利开源项目，并注明与哔哩哔哩官方无隶属或授权关系。
- 页脚展示广东主体备案号，并链接工信部备案官网。

## 页面内容

首页沿用仓库 `website/index.html` 的单页视觉结构，并调整为以下信息：

1. 主区域介绍面向 B 站直播场景的礼物互动工具，可把礼物事件转换为时间、积分和自定义属性规则，并在 OBS 中展示。
2. 当前本地开源版保留 GitHub 源码和最新版下载入口。
3. 受邀网页版展示为“建设中”状态，不提供不可用的登录按钮。
4. 功能区域介绍礼物互动规则、OBS 数据展示和开源可验证三个已有能力。
5. 页面明确不提供网络直播、音视频上传、论坛评论、新闻资讯或交易服务。

## 部署架构

上海轻量应用服务器运行 Nginx，静态文件位于 `/var/www/gift-panel`。三个域名在本阶段使用相同的虚拟主机和页面：

- `bilibililive.cn`
- `www.bilibililive.cn`
- `app.bilibililive.cn`

Nginx 提供：

- `/`：静态首页。
- `/healthz`：返回纯文本 `ok` 和 HTTP 200。
- 其他不存在的路径：返回 HTTP 404。

数据库继续只允许私网访问，服务器不开放数据库端口或应用内部端口。现有本地程序不作为公开服务运行。

## HTTPS 策略

第一阶段先保证 HTTP 页面可访问。随后为三个域名申请证书并启用 HTTPS，HTTP 自动跳转 HTTPS。若证书签发暂时受备案状态或域名校验影响，保留 HTTP 页面正常运行并记录原因，稍后重试。

## 安全边界

Nginx 配置以下安全响应头：

- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Referrer-Policy: no-referrer`
- 禁用摄像头、麦克风和定位权限的 `Permissions-Policy`
- 仅允许本站静态资源和既定外部跳转的内容安全策略

页面不使用第三方脚本，不向服务器提交表单，不设置用户 Cookie。

## 部署安全与回退

只操作上海实例 `bilibili-live-pilot`，不访问或修改北京实例。部署前检查现有 Nginx、监听端口和目标路径；如存在同名配置，先创建可恢复备份。新配置必须通过 `nginx -t` 后才能加载。配置检查失败时保留原服务状态，不启用错误配置。

## 验收标准

1. 三个域名均解析到上海服务器并显示相同首页。
2. 首页和 `/healthz` 返回 HTTP 200，不存在的路径返回 HTTP 404。
3. 浏览器标题为 `礼物互动工坊｜直播互动工具应用`。
4. 页面包含本地版下载、GitHub 源码、受邀网页版建设状态、非官方声明和服务边界说明。
5. 页脚展示正确的广东主体备案号并链接工信部备案官网。
6. 桌面端和手机端没有明显布局错误或横向溢出。
7. 服务器仅保留预期的公开监听端口，不公开 MySQL 或应用内部端口。
8. 从公网实际访问主域名、`www` 和 `app` 完成最终验证。

## 后续替换路径

受邀网页版完成多用户身份、邀请码绑定、单账号单房间租约、敏感信息保护和日志留存后，可将 `app` 域名切换到受保护的应用入口。主域名仍保留项目介绍与下载页，Nginx 入口和证书可以继续复用。
