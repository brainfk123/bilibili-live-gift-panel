# Bilibili 直播礼物属性面板插件 — 设计规格

日期：2026-07-31
状态：已确认

## 1. 概述

给 B 站主播使用的 OBS 浏览器源插件。核心功能：监听直播间礼物/SC 事件，按主播自定义的 **Excel 风格公式 + 条件规则** 累加 **多属性值**（如"加班时间"、"积分"），并在 OBS 中以醒目的独立面板实时展示。

分发形态：**单个 `index.html`**（Vite+TS 构建后 `vite-plugin-singlefile` 内联），主播拖进 OBS 浏览器源即用，**零运行时依赖**（仅需 OBS）。各主播通过各自的 OBS localStorage **独立配置**，互不影响。

合规提醒：使用 B 站 Web 端非官方弹幕协议，**仅私下分发**，禁止公开传播。

## 2. 架构

```
Vite+TS 工程
  └─ vite-plugin-singlefile 内联 → 单个 index.html → OBS 浏览器源
      ├─ 接入层   ：WebSocket 直连 B站弹幕服务器（匿名 uid=0，无需登录）
      ├─ 事件解析 ：SEND_GIFT（礼物）/ SUPER_CHAT_MESSAGE（醒目留言）
      ├─ 公式引擎 ：Excel 风格，自研解析器（不用 eval），安全无依赖
      ├─ 规则引擎 ：礼物 → 公式计算 → 条件校验 → 属性更新（msg_id 去重）
      ├─ 属性面板 ：?mode=display，OBS 用，只显示面板
      └─ 配置面板 ：?mode=config，浏览器打开编辑，共享同一份 localStorage
```

两种模式通过 URL 参数区分：`index.html?mode=display`（OBS 用）与 `index.html?mode=config`（浏览器配置用）。同源共享 localStorage。

## 3. 弹幕接入层（Web 端非官方协议）

流程：

1. 主播输入房间号（或 `live.bilibili.com/xxxx` 链接，自动解析数字）
2. 浏览器建立 WebSocket 到 `wss://broadcastlv.chat.bilibili.com/sub`
3. 发送认证包：`{uid:0, roomid:房间号, protover:2, platform:'web', buvid:随机值, type:2}`（匿名接入，**无需登录 B 站账号**）
4. 每 30 秒发送心跳包（B 站 60s 踢人，30s 安全）
5. 服务端消息为自定义二进制帧（16 字节 header + payload），`protover=2` 的批量包需 zlib 解压——用浏览器内置 `DecompressionStream('deflate')`，无需第三方库
6. 解析 payload 中 JSON 的 `cmd` 字段，只关心 `SEND_GIFT` 和 `SUPER_CHAT_MESSAGE`
7. 断线自动重连（指数退避），面板显示连接状态

**匿名兜底**：极少数情况 B 站可能要求先有 Cookie（buvid3）。实现内置"先匿名直连，被拒则先抓取匿名 buvid 再连"逻辑。全程不需要主播账号登录。

**身份确认**：`getDanmuInfo` 接口带风控（返回 -352），不依赖它；弹幕服务器地址 `broadcastlv.chat.bilibili.com` 为固定已知地址。

## 4. 公式引擎（Excel 风格）

语法仿 Excel，面向非编程用户：

| 要素 | 说明 | 示例 |
|---|---|---|
| 变量 | `price`=礼物单价(金瓜子)、`count`=本次赠送数量、`<属性名>`=当前属性值(按名引用) | `price/1000*60` |
| 运算符 | `+ - * /` 和括号 | `(price+100)/100` |
| 函数 | `IF(条件,a,b)`、`MAX()`、`MIN()`、`ROUND()`、`ABS()`、`RAND()`、`RANDBETWEEN(min,max)` | `IF(price>=10000,100,10)` |
| 条件比较 | `> < >= <= =` | `count>=10` |

要求：

- 自研极简解析器（tokenizer + AST + 求值），**禁止使用 eval**
- 公式框下方**实时预览**计算结果（输入时即时反馈）
- 语法错误给出中文提示（如"缺少右括号"）
- `RAND()` 与 `RANDBETWEEN()` **每次触发重新随机**（每次送礼抽一次，结果可不同）
- 属性值用 JavaScript 原生 `Number`（IEEE 754 double），量级最大约 1.8×10³⁰⁸，整数精确到 ±2⁵³

## 5. 规则引擎

**规则结构**（一个礼物可配多个规则）：

```
礼物 gift_id（按 gift_id 匹配，非名称）
 ├─ 触发 → 目标属性 + 公式
 └─ 条件：
     ├─ 上限封顶：属性达到 N 后不再累加
     ├─ 当日限次：当天最多触发 N 次
     └─ 最低门槛：price 低于 X 不触发（可选）
```

**执行流程**：

```
收到 SEND_GIFT → 解析(gift_id, 单价, 数量)
  → 查匹配规则（按 gift_id）
  → 校验条件（封顶/限次/门槛）
  → 公式计算增量（变量绑定 price/count/当前属性值）
  → 更新属性值（double，持久化 localStorage）
  → 面板动画反馈 + 记录变动日志
```

**防重复触发**：SEND_GIFT 是批量事件（一次可能合并多条），用礼物消息的 `msg_id` 去重。

## 6. 礼物同步（三层机制）

1. **内置礼物目录**：构建时抓取 `https://api.live.bilibili.com/xlive/web-room/v1/giftPanel/giftConfig`（匿名可用，返回全量礼物清单 gift_id/名称/价格/**图标**），生成内置 JSON 目录打进 HTML。主播可在配置面板按名称搜索整个目录直接选中配规则，无需知道 gift_id。B 站上新礼物 → 重新构建发新版。
2. **自动捕获**：收到任何不在目录里的礼物，自动进入"最近收到的礼物"列表并标记"未配置"，主播一键配置。纯 WebSocket 推送，零 CORS 问题。
3. **手动添加**：表单填 gift_id 或名称手动建规则。

**礼物图标**：`giftConfig` 响应含 `img_basic`(静态)、`img_dynamic`、`gif`/`webp`(动图)；`SEND_GIFT` 事件含 `gift_info.img_basic`。目录条目保存图标 URL。配置面板礼物列表显示图标（凭图识别）；属性面板触发动画展示礼物图标+名称。

注意：`giftConfig` 接口不带 CORS 头，浏览器直接 fetch 会被跨域拦截——仅构建期由开发机抓取，**插件运行时不需要调用该接口**。

## 7. 属性模型

- 多属性可扩展（如"加班时间"、"积分"）
- 每个属性字段：名称、初始值、**基础单位**（秒 / 无）、**显示格式**、当前值、清零操作
- 时间类属性：**按秒存储**，显示为 **HH:MM:SS 计时器风格**（如 `02:30:05`），超过 24h 显示天数（`2天 03:30:05`）
- 数字类属性：纯数字（整数/小数位可配）、或数字+单位后缀（如 `125 次`）
- 公式输出单位 = 属性基础单位

## 8. 界面

### 8.0 视觉设计语言（重要）

界面外观是核心验收标准之一，**默认观感必须精美**，而非"能用就行"。

**属性面板（直播画面里的核心）**：
- 深色半透明毛玻璃（glassmorphism）卡片，`backdrop-filter: blur`，适合叠加任何直播画面
- 渐变强调色（品牌紫 `#fb7299` 粉紫渐变），属性值大号显示（建议系统字体栈 + 数字等宽 `font-variant-numeric: tabular-nums`，避免跳动）
- 礼物触发动画：数值淡入放大 + 呼吸光晕 + 轻微粒子/流光，结束时平滑回落
- 连接状态用圆形呼吸灯（绿=已连接，黄=重连中，红=断开）
- 各区块圆角卡片 + 细边框描边，深色阴影，层次分明

**配置面板（浏览器里编辑）**：
- 现代深色主题（或跟随系统亮暗切换），侧边栏导航布局（房间/属性/规则/统计/设置）
- 卡片化表单、清晰的层级标题、按钮/输入框圆角与悬停反馈
- 公式编辑区高亮变量与函数名（简单语法着色），右侧实时预览卡片
- 空状态友好（无礼物时引导"送出第一个礼物后自动捕获"）
- 响应式，桌面浏览器为主，窄屏可堆叠

### 8.1 属性面板（?mode=display，OBS 用）

```
┌───────────────────────────────┐
│        加班时间               │  ← 属性名（样式可配）
│     02:30:05                  │  ← 大号当前值，礼物触发时跳动高亮
│  ❤ 礼物: 12  SC: 3           │  ← 今日统计（可选）
│  ● 已连接                     │  ← 连接状态角标
└───────────────────────────────┘
```

- 深色半透明或全透明背景（CSS 可配），适合叠加直播画面
- 可配置样式：字体、字号、颜色、对齐、触发动画
- 多属性纵向排列，每个属性一个区块
- 全屏无边框，OBS 浏览器源裁剪

### 8.2 配置面板（?mode=config，浏览器打开）

- **房间设置**：输入房间号，连接测试按钮
- **属性管理**：增删改属性（名称、初始值、单位、显示格式、手动调整/清零）
- **礼物规则**：搜索内置目录 / 最近收到礼物 / 手动添加 → 选礼物 → 选目标属性 → 填公式 → 配条件（封顶/限次/门槛）
- **今日统计**：每日礼物/SC 汇总，属性变动日志（谁送的、何时、+多少）
- **导出/导入配置**：下载/上传 JSON，方便主播换电脑迁移

## 9. 持久化（localStorage）

```
roomId        房间号
attributes    [{name, value, unit, format, ...}]
rules         [{giftId, attributeName, formula, cap?, dailyLimit?}]
settings      样式配置
giftCache     内置目录 + 最近收到的礼物（自动捕获增量）
stats         每日统计
```

所有写入即时持久化，OBS 崩溃/重启不丢。各主播 OBS 的 localStorage 独立 → 各自独立配置。

## 10. 错误处理

- 连接失败/断线：自动指数退避重连，面板显示"重连中…"状态
- 公式语法错误：配置时实时中文报错，不影响已保存的其他规则
- B 站协议变更：接入层集中处理，单点修改

## 11. 测试策略

- 公式引擎：纯函数，单元测试覆盖四则运算/函数/边界（除零、超大数、嵌套 IF、RAND 范围）
- 规则引擎：礼物事件→规则→属性链路，mock SEND_GIFT 数据测试去重、封顶、限次
- 协议解析：用录制的真实 SEND_GIFT 报文做 fixture 测试解压与字段提取
- 手动验证：连真实房间观察礼物到账累加（核心验收标准）

## 12. 待验证风险

1. **OBS CEF 的 file:// 下 localStorage 持久化**（Chrome/CEF 一般可用，首要验证点）。若不可用：回退为 OBS 本地静态服务（`python -m http.server`）或提示用 config 模式维护。
2. **匿名直连若被 B 站风控拒绝**：走 buvid 兜底逻辑。
3. **特殊短房间号**：部分直播间 URL 是短号，真实房间号可能不同。需要房间号解析兜底（若直连认证失败，尝试解析短号 → 真实房间号）。

## 13. 技术栈

- Vite + TypeScript
- `vite-plugin-singlefile`（构建内联为单 HTML）
- Vitest（单元测试）
- 无第三方运行时依赖（WebSocket/DecompressionStream 均为浏览器内置）
