# Hosted 管理端本地迭代设计

## 目标

在不连接生产服务、不发送真实邮件、不修改真实账号的前提下，用与生产相同的管理员组件和 CSS 搭建完整本地模拟器。管理员界面在本地反复验收，直到交互、布局、状态反馈和会话管理达到可上线标准，再接入真实 API、完成回归并部署。

本次解决以下已确认问题：

- 按钮、复选框、筛选器和表格操作排列不一致；
- 所有按钮缺少 hover、按下、键盘焦点、等待、成功和失败反馈；
- 原生 select/combobox、空状态、错误提示和创建成功提示没有正式样式；
- 创建邀请码后，排序、复制、分享或作废等列表操作可能让列表进入空白或失败状态；
- B站服务账号“立即检查”没有可见过程和结果反馈；
- 更换服务账号的二维码和继续按钮没有稳定的流程布局；
- 系统设置只支持一次性退出其他设备，无法查看授权设备、逐个退出或查看登录记录。

## 迭代边界

### 本地模拟器

新增一个只用于开发的管理员预览入口。它直接挂载生产管理员组件，但使用内存中的 Mock Hosted API。模拟器不加入 `vite.hosted.config.ts` 的生产输入，不进入 Hosted 镜像，也不读取浏览器中的生产 Cookie。

预览工具栏位于管理员框架之外，只在本地入口出现。它允许切换页面和状态：正常、空数据、等待、操作成功、操作失败及网络失败。模拟状态必须覆盖总览、主播账号、邀请码、B站服务账号和系统设置。

### 正式产品

正式组件、状态模型、API 类型、后端接口、数据库迁移和 CSS 属于产品修改，需要测试、提交和上线门禁。模拟数据、场景切换器、临时截图和本地预览报告属于实验资产，默认不提交和不进入生产包。

## 统一交互系统

管理员内容区域使用一套明确的控件语义：

- `primary`：创建、保存、确认等主要动作；
- `secondary`：检查、复制、查看详情等普通动作；
- `quiet`：取消、清除选择、关闭等弱动作；
- `danger`：停用、作废、退出设备等破坏性动作。

所有按钮必须具备默认、hover、active、focus-visible、disabled 和 busy 状态。busy 状态保留原宽度，显示小型 spinner 和动作文本，防止重复提交。成功或失败不靠永久改写按钮名称表达，而由与动作关联的状态条或 toast 呈现，并为屏幕阅读器设置 `aria-live`。

Select 使用统一外壳、箭头、焦点环、字号和高度；复选框使用固定尺寸、圆角、边框和勾选状态，不再依赖浏览器默认巨大蓝色样式。所有控件保留原生语义和键盘操作，不实现自制下拉菜单。

页面级空状态、错误状态和操作提示使用统一的 `notice` 组件。错误提示包含“重试”动作；空状态包含解释和可执行的下一步；成功提示可自动消退，也能手动关闭，但关闭提示不得改变业务数据。

在 `prefers-reduced-motion: reduce` 下禁用位移动画和旋转之外的非必要动画；普通模式下动画时长控制在 120–180ms。

## 页面设计

### 总览

指标卡保持三列布局。资源入口改为带说明和方向图标的二级卡片，而不是三个孤立的蓝色按钮。没有最近活动时显示正式空状态。优先处理项保持可点击，并提供 hover/pressed 反馈。

### 主播账号

搜索和两个筛选器进入同一响应式筛选栏：搜索占剩余空间，筛选器有标签和统一宽度。批量工具栏只在选中账号后出现。表头与行复选框使用统一样式，并分别提供“全选当前页”和账号选择的可访问标签。

批量动作有进行中和结果摘要；失败项保留选择，成功项取消选择。详情面板继续作为侧边抽屉，但按钮按普通、危险动作分组。

### 邀请码

搜索、状态筛选和“创建邀请码”位于同一工具栏。创建面板以紧凑的可折叠卡片显示数量、有效期、创建和取消。

邀请码列表数据、加载状态和提示状态分别保存。复制、分享和关闭成功提示不得触发列表重载或清空列表。排序、筛选、创建和作废可以触发受代次保护的重载；若重载失败，保留上一份成功列表并在列表上方显示错误提示，而不是用错误文本替换整个表格。

创建成功后立即合并新记录，并显示包含数量、复制结果和有效期的成功提示。作废成功只更新目标记录；服务器刷新失败时仍保留本地已知状态并提供重试。

无邀请码时显示正式空状态和“创建第一个邀请码”按钮。

### B站服务账号

状态使用独立卡片展示健康、掩码 UID、最近验证和最近替换时间。“立即检查”进入 busy 状态，完成后显示“检查完成，状态正常”或可重试错误；按钮不得无反馈地恢复。

更换流程使用分步卡片：

1. 创建二维码；
2. 二维码居中显示，下面显示有效期、重新生成和取消；
3. 用户确认扫码后进入 TOTP 授权；
4. 替换中显示明确等待状态；
5. 完成后关闭流程并刷新状态。

二维码宽度受容器约束，继续按钮固定在二维码下方，不使用绝对定位或依赖图片高度的布局。

### 系统设置与会话

设置页分为“管理员资料”“已授权设备”“登录记录”“诊断”和“退出登录”。

已授权设备每行展示：设备/浏览器名称、当前设备标记、首次登录时间、最近活动时间、会话到期时间和模糊 IP。支持逐个退出非当前设备；“退出其他设备”显示将受影响的设备数量并要求确认。当前设备不能通过该列表自我撤销，只能使用“退出管理员登录”。

登录记录展示最近的成功和失败登录：时间、结果、设备/浏览器和模糊 IP。记录只展示有限窗口，不包含邮箱验证码、会话令牌、完整 IP、Cookie 或原始 User-Agent。

后端为会话增加设备摘要、创建时间、最近活动、到期时间和模糊 IP 投影；登录审计增加结果和安全的客户端摘要。API 只返回允许字段。单设备撤销和批量撤销都必须验证当前管理员会话、CSRF 和 Origin。

## 状态与错误处理

所有异步操作使用独立状态，不共用一个会覆盖页面内容的 `textContent` 容器。页面销毁或请求代次过期后不得更新 DOM。网络失败保留已知数据并允许重试；业务失败显示明确原因但不暴露数据库、Token、邮箱验证码、完整 IP 或 B站凭据。

复制和系统分享单独处理权限或取消结果。用户取消系统分享不显示错误；剪贴板失败提供“手动选择代码”降级。

## 测试与验收

开发遵循 RED/GREEN：

- DOM 测试覆盖统一按钮、select、checkbox、notice 和 reduced-motion 契约；
- 邀请码测试复现“操作后列表清空”，证明失败刷新保留旧列表，复制/分享不触发重载；
- B站服务测试覆盖检查中、成功、失败、二维码重新生成、取消和 TOTP 步骤布局；
- 设置页测试覆盖设备列表、登录记录、单设备退出、批量退出和当前设备保护；
- Go 测试覆盖会话投影、审计投影、鉴权、撤销事务和隐私字段拒绝；
- 本地模拟器逐页检查桌面和 390×844 手机尺寸，不允许横向溢出；
- 上线前运行前端全量、TypeScript、Go 全量、go vet、关键 race、MySQL 8.4 集成、Hosted 镜像构建及可复现性验证。

只有用户在本地模拟器确认所有页面、自动化门禁全部通过、生产备份与回滚材料准备完成后，才允许重新部署香港 Hosted 服务。master、上海服务器、国内更新镜像、其他 COS 路径和发布系统继续保持独立。
