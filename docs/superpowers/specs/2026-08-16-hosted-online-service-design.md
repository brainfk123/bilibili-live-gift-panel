# 邀请制在线直播互动服务设计

日期：2026-08-16
状态：已批准
目标分支：`codex/hosted-service`

## 1. 背景与目标

当前项目以 Windows 本地 EXE 运行。新版本要允许主播只打开网站、使用已绑定的 B 站账号登录，即可配置玩法、连接任意有效直播间并向 OBS 提供展示页面。

一期目标：

- 约 50 个已注册主播账号，最多 10 个账号同时运行。
- 使用邀请码注册；管理员授予邀请码额度，主播在额度内自行生成邀请码。
- 主播登录用 B 站 UID 与目标直播间相互独立。
- 每个主播账号同一时间只运行一个目标直播间，账号配置随账号移动。
- 多个账号选择同一房间时，共享一条 B 站上游连接，但配置、状态和历史相互隔离。
- 提供从本地 EXE 向当前在线账号复制配置和当前玩法状态的迁移功能。
- B 站观众身份只存在于当前直播会话内存，不写业务数据库、日志或备份。
- 国内节点只保留公开静态下载；在线多用户服务放在香港独立域名。

本设计优先保证：租户隔离、凭证安全、事件一致性、可恢复性、低运维成本以及对 B 站出口风控的克制处理。

## 2. 非目标

一期明确不做：

- 不在 `master` 中加入托管登录、邀请码或多租户服务代码。
- 不支持主播上传图片、音频、视频、SVG、HTML、JavaScript 或压缩包。
- 不抓取迁移文件或配置中提供的任意外部 URL。
- 不区分主播、运营、房管等子角色。
- 不提供手动开始或停止运行按钮。
- 不为每个主播长期保管其 B 站 Cookie，也不使用主播登录凭据采集直播数据。
- 不持久化观众 UID、昵称、头像或可跨会话建立观众画像的数据。
- 不引入 Kubernetes、微服务、Redis、消息队列或多节点高可用。
- 不通过国内个人备案节点反向代理、隐藏或加速香港在线业务。
- 不使用轮换代理或出口分片规避 B 站风控。

## 3. 代码与分支策略

- `master` 继续作为本地 EXE 的正式开发和发布分支。
- 在线服务在长期分支 `codex/hosted-service` 开发。
- 实施时从确认的 `master` 基线建立独立 Git worktree，不切换或污染当前工作目录。
- 本地版的通用功能可以从 `master` 定期单向合并到在线分支。
- 在线认证、邀请码、数据库、多租户运行时等托管功能不得整体反向合并到 `master`。
- 两个版本使用独立版本号、构建任务、产物、部署流水线和发布说明。
- 规则计算、配置规范化等真正通用的能力应保持为无平台依赖的深模块；避免在线分支复制代码后永久分叉。

本设计阶段不创建分支、不移动现有未提交修改，也不修改实现代码。

## 4. 部署拓扑

### 4.1 国内静态下载节点

现有中国内地腾讯云节点只提供：

- 本人维护的免费开源软件安装包；
- 版本清单、校验文件和许可证；
- 与备案展示要求一致的静态页面。

该节点不提供主播登录、邀请码、在线配置、OBS 页面、房间 API、用户专属文件或香港业务反向代理。保留腾讯云客服确认材料，并以最终备案/接入商要求为准。

### 4.2 香港在线服务节点

一期采用腾讯云香港 Lighthouse Linux 单机部署：

- Nginx：TLS 终止、安全响应头、静态资源、请求体限制和入口限流；
- Go 模块化单体：网站 API、后台任务、B 站连接和账号运行时；
- MySQL 8：业务数据、配置版本、无身份统计和审计；
- 进程内运行时：当前观众身份、账号队列、房间共享源和实时广播；
- 香港 COS：加密数据库备份和日志归档。

MySQL 仅监听本机 Unix Socket 或容器私网，不开放公网端口。公网只开放 80/443；80 仅跳转 HTTPS。SSH 限制来源、禁用密码直登并使用密钥。

一期不引入 Redis 或消息队列。未来需要多节点时，可把 `RoomSource` 和账号运行时拆成工作节点，再增加分布式租约与消息基础设施；数据库模型和前端 API 不应因此重做。

## 5. 服务端模块边界

Go 服务内部划分为：

- `Identity`：B 站 UID 验证、主播账号、本站会话和账号绑定；
- `AdminIdentity`：唯一管理员、TOTP、恢复码和近期再验证；
- `Invitation`：额度、邀请码生成/撤销/兑换和邀请关系；
- `Configuration`：配置版本、当前玩法状态、编辑和回滚；
- `Migration`：迁移包解析、预览、应用、待应用和回滚；
- `Runtime`：运行租约、账号状态机、直播会话和房间切换屏障；
- `BiliGateway`：服务账号凭证、统一 HTTP 调用、限流、缓存和出口熔断；
- `RoomSource`：按规范化房间号共享上游长连接并分发不可变事件；
- `OBS`：只读页面、令牌交换和短期 OBS 会话；
- `Audit`：结构化安全日志、审计事件和归档；
- `Admin`：账号管理、额度调整、例外换绑和系统健康状态。

强制边界：

- 所有 B 站请求必须经过 `BiliGateway`；业务模块不得自行访问 B 站。
- 所有配置修改必须经过带版本号的 `Configuration`；运行时不得直接覆盖配置 JSON。
- 所有租户数据访问都要求显式 `account_id`，禁止从客户端提交目标账号 ID 后直接信任。
- `RoomSource` 只能分发事件，不能持有某个主播账号的规则或统计。

## 6. 身份与认证

### 6.1 主播账号

- 一个主播账号唯一绑定一个已验证的 B 站 UID。
- 注册和登录时使用 B 站验证流程取得临时凭据，只读取确认身份所需的 UID。
- UID 验证完成后立即丢弃主播 B 站临时凭据；直播数据访问不使用主播凭据。
- 主播不能自助解绑或换绑。
- 原 B 站账号不可用时，由管理员核验后执行例外换绑，记录旧 UID、新 UID、原因和时间；不消耗新邀请码。
- 当前不提供账号类型或子角色。

本站会话使用高熵随机令牌，数据库只保存哈希；浏览器使用 `Secure`、`HttpOnly`、合理 `SameSite` 的 Cookie，并配合 CSRF/Origin 校验。登录、注册、二维码和会话刷新均实施账号、IP 与全局三级限流。

### 6.2 唯一管理员

- 管理员身份只能通过服务器本地初始化建立，系统中只有一个所有者身份。
- 日常登录先验证预设 B 站 UID，再验证标准 TOTP；可使用 Google Authenticator。
- 额度调整、例外换绑、服务账号重置、管理员恢复等高风险操作要求近期 TOTP 再验证。
- 管理员恢复仍需先验证管理员 B 站 UID。
- 初始化或重置时生成一次性恢复码，服务器只保存哈希。
- 恢复码可以通过已验证邮箱发送，但只能放入 AES-256 加密文件；解密密码只在当前页面显示一次，不能随邮件发送。
- 恢复成功后立即撤销所有管理员会话、旧 TOTP 和旧恢复码。

### 6.3 B 站服务账号

- 使用由管理员控制的独立 B 站服务账号统一访问所需直播数据。
- 服务账号应与管理员日常主账号及资产账号分离。
- 凭证使用应用主密钥加密保存，禁止写入日志、备份正文或错误响应。
- 长期方向是评估并迁移到 B 站正式开放平台/开放直播授权；单出口或出口分片不能替代接口授权。

## 7. 邀请码与额度

### 7.1 额度

- 管理员可以为任意主播配置邀请码额度；管理员自身创建邀请码不受额度限制。
- 主播每成功生成一个邀请码立即扣减一份额度。
- 撤销、过期、兑换失败或账号停用均不自动返还额度。
- 新注册主播的初始额度为零，邀请码额度不从邀请人转移或继承。
- 所有管理员额度调整写不可修改的调整记录，包含操作人、前后值、时间和备注。

### 7.2 邀请码生命周期

- 完整邀请码只在生成成功页面显示一次。
- 数据库只保存邀请码哈希、掩码提示、创建者、状态和时间信息。
- 状态至少包括 `active`、`used`、`revoked`、`expired`。
- 撤销后仍永久保留可展示记录，不能重新启用。
- 兑换后永久失效；受邀账号以后停用、删除或换绑也不能恢复邀请码。
- 邀请关系只用于后台展示和风险追溯，不产生上下级管理权限。

兑换顺序：先完成 B 站 UID 验证，再在一个数据库事务中检查邀请码并创建绑定；并发兑换只有首个事务成功。验证失败或中途退出不改变邀请码状态。

## 8. 房间、运行租约与共享上游

### 8.1 账号与房间

- 登录 UID 与目标直播间独立；主播可输入任意有效房间号。
- 一个主播账号同一时间最多有一个活动目标直播间。
- 账号配置随账号存在，不因房间切换复制或丢失。
- 房间切换结束旧直播会话并创建新会话；历史记录保留当时房间号和配置版本。

### 8.2 自动运行租约

- 打开在线配置页面或 OBS 页面会维持运行租约。
- 存在有效房间且任一类页面在线时，服务器自动建立或唤醒运行时。
- 两类页面都离线满 10 分钟后，服务器自动排空队列、结束直播会话并休眠。
- 不提供手动开始或停止按钮。

### 8.3 共享房间源

- 服务器以 B 站规范化房间号作为 `RoomSource` 键。
- 多个账号选择同一房间时只建立一条上游长连接。
- `RoomSource` 把同一不可变事件分发给各账号的串行运行队列。
- 每个账号使用自己的配置、状态、统计和 OBS 订阅处理事件；任何账号异常不得影响共享源或其他账号。

## 9. 礼物事件一致性与故障降级

处理顺序：

1. 标准化房间、事件类型和可用的稳定事件 ID。
2. 共享源向相关账号分发不可变事件。
3. 每个账号串行计算规则结果。
4. 在 MySQL 事务中写入属性状态、活动进度、礼物目标进度、无身份统计和可用的去重凭据。
5. 数据库提交成功后才向该账号 OBS 广播新状态。

这保证 OBS 已显示的持久玩法变化不会因普通服务重启而回退。

去重策略：

- B 站提供稳定事件 ID 时，保存其哈希作为短期去重凭据。
- 没有稳定事件 ID 时，只能在当前进程内做短期指纹去重；服务重启后无法绝对消除极少量重复，必须记录为已知边界。
- 去重记录不得包含观众 UID、昵称或头像。

故障处理：

- MySQL 暂时不可用时暂停提交玩法变化，在内存中短暂、有限地缓冲事件，并向配置页/OBS 显示降级状态。
- 缓冲超过时间或数量上限后停止接受新的规则变化并告警，不假装正常运行。
- B 站断连采用指数退避、抖动和错峰重连。
- 同出口出现相关性拒绝或风控时启用全局熔断，禁止所有账号各自高速重试。
- 优雅重启先停止接收新租约，最多等待 30 秒排空已进入处理队列的事件。
- 房间切换使用屏障：封闭旧队列并完成持久化后，才开始新房间会话。
- 单账号规则异常只隔离该账号运行时。

## 10. 观众隐私与业务记录

观众 B 站 UID、昵称、头像及当前贡献榜：

- 只在当前直播会话内存中用于实时互动和展示；
- 不写 MySQL、普通日志、审计记录、迁移包或备份；
- 会话结束或服务重启后丢失并从空状态重新开始。

会话结束后可持久化：

- 礼物种类、数量和金额；
- 规则触发与属性变化结果；
- 活动和礼物目标结果；
- 不含观众身份的聚合统计。

持久记录必须标记账号、规范化房间、直播会话和当时配置版本，避免房间切换或配置迁移后混淆。

## 11. 配置版本与当前玩法状态

配置定义和频繁变化的当前状态分开保存：

- `account_config_versions`：追加式、不可原地修改的完整规范化配置定义；
- `account_runtime_state`：属性当前值、活动状态、里程碑进度、礼物目标完成数量及状态修订号；
- `streamer_accounts.active_config_version_id`：账号当前生效的配置版本；
- `live_sessions.config_version_id`：直播会话开始时引用的配置版本。

普通配置保存采用乐观版本控制；客户端提交旧修订时返回冲突并要求刷新，不能静默覆盖其他页面的新改动。运行事件按账号串行并在事务中更新状态修订。

## 12. 本地 EXE 数据迁移

### 12.1 采用方案

一期采用文件迁移：本地 EXE 导出专用 JSON，主播登录网站后上传并确认。一次性配对码直传作为未来体验优化；不接受完整数据目录或原始运行文件。

迁移是复制，不会删除或修改本地 EXE 数据。

### 12.2 迁移内容

迁移：

- 属性定义及当前数值；
- 礼物规则、定时规则和公式预设；
- 展示场景、主题和面板布局；
- 活动配置、当前状态和里程碑进度；
- 礼物目标定义及当前完成数量；
- 简易玩法配置；
- 被上述配置引用的礼物 ID、名称、价格等非 URL 目录元数据；素材 URL 不从迁移包导入，由 B 站网关按官方响应重新解析；
- 本地房间号，仅作为待确认的建议值。

排除：

- 所有 B 站 Cookie、令牌和登录存储；
- 观众 UID、昵称、头像、贡献榜和礼物明细；
- 运行日志、诊断记录、WAL、缓存和去重状态；
- 本地媒体、裁剪数据、文件路径和 FFmpeg 设置；
- 自动更新、教程进度等桌面专属设置。

### 12.3 文件契约与校验

文件名建议为 `gift-panel-migration-v1.json`，顶层包括：

- `kind`；
- `migrationVersion`；
- 来源 EXE 版本、配置结构版本和导出时间；
- 白名单配置与当前状态负载。

迁移版本独立于桌面配置备份版本。服务端不信任文件自带哈希，而是在白名单规范化后计算 SHA-256 用于幂等。

服务端规则：

- 只接受 JSON，最大 2 MiB；
- 限制嵌套深度、字段数、数组长度和字符串长度；
- 按白名单重新构造对象，多余字段在预览中提示忽略；
- 通过逐版本转换器支持已知旧格式；
- 对更新且未知的格式拒绝导入，不能强行或静默丢字段；
- 不根据文件中的 URL 主动抓取内容；
- 原始上传文件不写磁盘、对象存储、日志或备份。

### 12.4 预览、应用和回滚

流程：

1. 当前已登录主播上传迁移包。
2. 服务端校验并生成“将迁移、将忽略、不兼容”预览。
3. 主播确认目标账号和可选建议房间。
4. 登录状态超过 15 分钟时重新进行一次 B 站 UID 验证。
5. 在线账号无活动会话时立即原子应用。
6. 在线账号正在运行时保存为待应用迁移；当前会话自然结束后自动切换，期间可以取消。

迁移整体替换当前配置和当前玩法状态，不做字段级合并。旧在线历史会话和无身份统计不删除。

应用前保存配置版本及当前玩法状态快照，七天内允许回滚。回滚恢复迁移前的在线配置与当前玩法状态，不更改本地 EXE，也不恢复或删除历史直播会话。

原始文件只存在于请求处理期间；规范化预览草稿最多保留 24 小时。同一账号每天最多发起 5 次迁移预览。

`migration_jobs` 状态至少包括：`previewed`、`pending`、`applied`、`cancelled`、`failed`、`rolled_back`。

## 13. OBS 访问

- OBS 页面只读，不能修改配置、房间或账号。
- 完整 OBS 长期令牌只在创建/重置时显示一次，数据库只保存哈希。
- 推荐分享地址把长期令牌放在 URL fragment；fragment 不进入 Nginx 请求日志。
- 页面加载后用 fragment 令牌交换短期、只读 OBS 会话，并立即通过 `history.replaceState` 清除地址栏中的令牌。
- OBS 会话限定账号和展示资源，设置过期时间，可由主播重置并立即撤销旧会话。
- 页面通过 WebSocket 或 SSE 接收小型状态快照与增量更新，不轮询完整账号配置。

## 14. 数据库模型

核心表按职责划分：

- `admin_identity`、`admin_totp`、`admin_recovery_codes`；
- `streamer_accounts`、`bili_uid_bindings`、`site_sessions`；
- `invitation_quotas`、`invitation_quota_events`、`invitations`；
- `account_config_versions`、`account_runtime_state`；
- `migration_jobs`；
- `live_sessions`、`session_aggregates`、`event_dedup_receipts`；
- `obs_credentials`、`obs_sessions`；
- `service_credentials`；
- `audit_events`。

数据保护：

- B 站 UID 加密保存，同时保存不可逆 HMAC 用于唯一性查询；不以明文 UID 建索引。
- 邀请码、本站会话、OBS 凭证和恢复码只保存哈希及必要掩码提示。
- B 站服务凭证和管理员 TOTP 密钥使用带密钥版本的 AEAD 加密，HMAC 与加密使用不同用途的密钥。
- 应用主密钥不进入数据库或数据库备份，单独加密离线保存。
- 数据库事务和唯一约束必须负责邀请码并发兑换、额度非负、UID 唯一绑定和配置版本切换，不能只依赖应用层检查。

## 15. 日志、审计与备份

### 15.1 日志

结构化运行日志可记录：内部账号 ID、请求 ID、事件类型、礼物 ID/数量、房间内部标识、外部接口状态、连接过程、耗时、错误码和错误栈。

禁止记录：B 站 Cookie/令牌、本站会话原文、完整邀请码、完整 OBS 令牌、恢复码、观众 UID/昵称/头像和迁移配置正文。

- 本机保留最近 30 天热日志。
- 更早日志加密归档到香港 COS。
- 网络运行、安全事件、认证结果、系统维护等相关日志合计至少保留六个自然月。
- 审计记录不可编辑；仍参与邀请码或账号约束的业务状态不因日志到期而消失。

### 15.2 备份

- 每日生成加密 MySQL 备份并上传独立香港 COS 存储桶。
- 保留 7 份日备份、4 份周备份和 6 份月备份。
- 生产服务账号只允许向指定备份前缀写入，不授予删除历史备份权限。
- 每月执行一次实际恢复演练并记录恢复点和恢复耗时。
- 数据库备份与应用主密钥分离保存。
- 主密钥丢失时，业务配置和无身份统计仍可恢复，但管理员 TOTP 与 B 站服务账号必须重新绑定。

## 16. 安全基线

- Linux 最小化安装，及时安装安全更新；容器/进程以非 root 用户运行。
- 只公开 80/443，数据库和内部管理端口不对公网开放。
- Nginx 设置 TLS、HSTS（确认所有子域 HTTPS 后再启用 includeSubDomains）、CSP、点击劫持和 MIME 嗅探防护。
- 所有状态修改接口执行 CSRF/Origin 校验；所有数据库访问显式检查租户归属。
- 登录、二维码、邀请码、迁移、OBS 交换和 B 站调用实施分层限流。
- 机密使用独立密钥加密，密钥文件权限最小化，禁止进入镜像和 Git。
- 配置、迁移和 API 输入执行严格结构/范围校验；不支持自定义 HTML/JS 或任意上传。
- 安全错误对外返回稳定错误码，对内通过请求 ID 关联脱敏日志。
- 监控 CPU、内存、磁盘、MySQL 连接、请求错误率、事件队列长度、B 站重连/风控、运行账号数、房间源数、备份和证书到期。
- 磁盘、数据库连接或事件队列达到阈值时主动降级和告警，避免静默损坏。

## 17. B 站出口风险控制

B 站未公开 Web Cookie 接口的同 IP 多账号上限，也未公开适用于本项目的完整 QPS 边界，因此不能用一个自创账号数阈值承诺安全。

一期采用：

- 单一、固定的香港出口；
- 全局、账号、端点三级限流；
- 礼物目录等高放大接口使用缓存和 singleflight；
- 房间连接错峰和带抖动退避；
- 出口级熔断与可观测指标；
- 独立 B 站服务账号，不轮换代理。

只有指标证明故障与出口强相关且缓存/退避无法改善时，才评估固定出口分片。本地桥接可作为反复风控或不再适合托管凭证时的降级方向，但不属于一期。

## 18. 容量与成本边界

一期容量基线：

- 50 个注册账号；
- 10 个同时活动账号；
- 同房间账号共享上游连接，因此实际上游连接数不超过同时活动的不同房间数；
- 迁移文件不超过 2 MiB；
- OBS 使用增量推送，禁止每秒轮询完整配置。

已选香港入门方向为 Linux 2 核 4 GB Lighthouse。2026-08-14/15 调研时公开或购买页口径约为 90 元/月；COS 备份、邮件、域名和实际超额流量另计，最终以购买页和账单为准。试运行先购买一个月并做至少七天三网观测，再决定续费或升级。

2 核 4 GB 需要限制 MySQL 缓冲池与 Go 进程内存并设置告警。扩容依据是 CPU、内存、队列延迟、不同房间源数量、数据库延迟、香港链路质量和 B 站风控指标，不按注册账号总数机械扩容。

- 根据指标决定是否扩大到 50/10 基线。

## 20. 验收标准

上线试运行前至少满足：

1. 并发兑换同一邀请码只能成功一次，额度不会变负。
2. 主播无法读取或修改其他账号的配置、迁移、OBS 和历史数据。
3. 主播 B 站临时登录凭据在 UID 验证后被销毁。
4. 管理员高风险操作必须通过近期 TOTP 验证，恢复会撤销全部旧凭据。
5. 一个账号不能同时运行两个房间；切换屏障不会把旧事件写入新会话。
6. 多账号选择同房间时只有一条上游连接，账号状态仍完全隔离。
7. 配置页或 OBS 在线可自动运行；两者离线十分钟后自动休眠，且不存在手动停止入口。
8. OBS 只读令牌不会出现在 Nginx URL 日志，重置后旧令牌立即失效。
9. 数据库、日志、备份和迁移包中检索不到观众 UID、昵称、头像及任何明文访问凭证。
10. 数据库提交失败时 OBS 不广播未持久化的玩法变化。
11. 迁移预览不会修改配置；重复迁移幂等；运行中迁移只在会话结束后生效；七天内可恢复迁移前配置和状态。
12. 未知新迁移格式被安全拒绝，旧格式通过固定样例验证升级结果。
13. 备份可在隔离环境实际恢复，且没有应用主密钥时不会泄露加密凭证。
14. 10 个活动账号的容量测试满足目标延迟和内存阈值，单账号异常不会拖垮其他账号。
15. B 站断连、限流和全局熔断均有可观察状态与脱敏日志。

## 21. 延后决策

以下事项不阻塞一期，但需要在相应阶段开始前单独确认：

- 香港在线业务使用的最终独立域名；
- 邮件发送服务及管理员恢复邮件模板；
- 配置页面的最终视觉和品牌文案；
- B 站正式开放平台/开放直播接入可行性；
- 超过单机容量后的固定出口分片或多节点方案；
- 是否在二期提供网站配对码，由 EXE 直接推送迁移数据。
