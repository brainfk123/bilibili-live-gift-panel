# 属性编辑器随机范围、时间输入与规则冻结设计

日期：2026-08-14

## 背景

当前小白模式把随机增加和随机减少作为两个选项，只能输入一个正数；时间格式属性在编辑器里仍以总秒数显示；编辑属性期间，后台礼物规则和定时器仍可能并发修改正在编辑的属性。这三处行为会增加配置难度，并可能让保存结果覆盖直播期间发生的属性变化。

本设计完成三项相关改进：

1. 把随机增加与随机减少统一为带符号的随机变化范围。
2. 为时间格式属性提供可校验的时分秒天输入和快捷加减按钮。
3. 编辑已有属性时，只冻结该属性的自动礼物规则和定时器规则。

## 目标与非目标

### 目标

- 小白模式使用一个随机变化选项表达只增加、只减少或随机增减。
- 兼容并正确识别已经保存的随机增加、随机减少公式。
- 时间属性编辑时不再要求用户换算总秒数。
- 编辑已有属性期间，后台不会并发改变该属性值。
- 其他属性、礼物记录、贡献、盲盒和统计继续正常运行。
- 页面异常退出后，冻结状态能够自动恢复。

### 非目标

- 不改变配置文件中时间属性的存储单位；仍保存总秒数。
- 不改变 OBS 时间显示协议。
- 不回放或补算编辑期间跳过的礼物规则和定时器规则。
- 不冻结其他属性，也不冻结模板选择页、活动编辑器或外观编辑器。
- 不把临时冻结状态写入用户配置。

## 一、统一随机变化

### 用户界面

小白模式删除独立的“随机增加”和“随机减少”选项，统一显示“随机变化”。选择后显示两个整数输入：

- 最小变化
- 最大变化

示例：

- `-60` 到 `60`：随机增加或减少。
- `-60` 到 `-1`：只随机减少。
- `1` 到 `60`：只随机增加。
- `0` 到 `0`：保持当前值。

输入必须满足：

- 两端均为整数。
- 最小变化不大于最大变化。
- 允许负数、零和正数。

属性计算结果始终不低于 `0`。现有属性最大值限制继续可用。

### 公式语义

无最大值限制时生成：

```text
MAX(属性 + RANDBETWEEN(最小变化, 最大变化), 0)
```

设置最大值限制时生成：

```text
MIN(MAX(属性 + RANDBETWEEN(最小变化, 最大变化), 0), 最大值)
```

### 旧配置兼容

不进行破坏性配置迁移。打开旧规则时，快速规则识别器按以下方式映射：

- `属性 + RANDBETWEEN(1, N)` 映射为 `1` 到 `N`。
- `MAX(属性 - RANDBETWEEN(1, N), 0)` 映射为 `-N` 到 `-1`。
- 已带最大值限制的旧随机增加公式保留该限制。

用户保存编辑后的规则时，公式改写为新的规范形式。无法安全识别的自定义公式继续作为高级公式显示，不做猜测性转换。

## 二、时间格式属性编辑

### 输入格式

当属性格式为时间时，“当前值”使用时间文本输入，而不是显示总秒数。支持：

```text
时:分:秒
天:时:分:秒
```

示例：

- `02:30:45` 表示 2 小时 30 分 45 秒。
- `36:00:00` 表示 36 小时。
- `1:02:30:45` 表示 1 天 2 小时 30 分 45 秒。

校验规则：

- 只允许三段或四段格式。
- 每段必须是非负整数，不允许空段、小数、正负号或其他字符。
- 分和秒必须在 `0–59`。
- 三段格式的小时可大于 `23`。
- 四段格式的小时必须在 `0–23`。
- 天数必须为非负整数。
- 解析后的总秒数必须是 JavaScript 安全整数和后端可接受的有限数值。

非法输入阻止保存，并给出针对段数或具体字段的稳定中文提示。

### 规范显示

- 总时长不足一天时，规范显示为 `HH:MM:SS`；小时至少两位，但允许超过两位。
- 总时长达到一天时，规范显示为 `D:HH:MM:SS`。
- 分、秒以及四段格式中的小时固定补齐两位。
- 后端和配置文件仍保存总秒数。

### 快捷按钮

时间输入下方提供：

- `-1时`
- `-10分`
- `-30秒`
- `+30秒`
- `+10分`
- `+1时`

按钮只修改当前编辑草稿，不提前保存。减时结果最低为零，并立即以规范时间格式回填。若文本当前非法，按钮不猜测数值，而是先提示用户修正输入。

切换到时间格式时，将当前有限非负数值视为总秒数并格式化；切换离开时间格式时，必须先成功解析当前时间文本。

## 三、按属性冻结规则

### 冻结范围

只有编辑已有属性时创建冻结租约。新建属性没有既有规则，不需要冻结。

冻结仅作用于指向该属性的：

- 自动礼物规则
- 自动定时器规则

以下行为不冻结：

- 其他属性的礼物规则和定时器规则
- 礼物收据
- 礼物、用户贡献和盲盒统计
- 礼物目录和最近礼物
- 用户在属性编辑器中保存的新当前值

编辑期间跳过的规则不排队、不回放。定时器即使因冻结被跳过，也正常推进下一次计划时间，退出编辑后不会集中补执行。

### 临时租约模型

后台维护并发安全的内存租约协调器。每条租约包含：

- 稳定属性 ID
- 随机且不可预测的会话令牌
- 到期时间

配置页打开已有属性工作台前创建租约；创建失败则不打开编辑器。配置页每 5 秒续租，租约在 15 秒未续租后自动失效。正常取消、保存、关闭和页面卸载会进行 best-effort 释放。

同一属性允许存在多个编辑会话。只要任意租约仍有效，该属性就保持冻结。改名不会解除冻结，因为规则执行时会根据属性名称找到属性，再以稳定属性 ID 查询冻结状态。

租约完全是运行时状态，不进入 `config.json`，也不参与正式配置事务。

### 保存和释放时序

保存已有属性时严格遵循：

1. 保持租约有效。
2. 前端校验编辑草稿。
3. 后台校验并持久化配置。
4. 收到保存成功响应。
5. 关闭编辑器。
6. 释放租约并刷新配置视图。

保存失败时编辑器保持打开，租约继续续期。取消或关闭时不保存草稿，立即释放租约。

### 续租异常

续租失败时显示持续、可见的中文警告并自动重试，不能静默假装仍在冻结。租约到期是页面崩溃、进程异常和无法正常释放时的最终恢复机制。

## 四、模块边界

### 前端随机规则模块

快速规则模块负责：

- 新随机范围草稿模型。
- 规范公式生成。
- 新旧公式识别。
- 区间和最大值校验。

配置页面只负责渲染控件和展示错误，不重复解析公式。

### 前端时间输入模块

独立纯函数模块负责：

- 总秒数格式化。
- 三段和四段时间解析。
- 快捷增减和零值截断。
- 稳定错误分类。

属性编辑器消费这些函数，不在 DOM 回调中手写时间换算。

### 后台租约协调器

独立 Go 组件负责：

- 创建、续租、释放和按到期时间清理租约。
- 查询某个稳定属性 ID 是否被冻结。
- 多会话和并发安全。

HTTP 处理器负责同源保护、请求大小限制、方法、属性 ID、会话令牌和 JSON 校验。规则执行器只依赖“属性是否被冻结”的窄接口，不依赖 HTTP 或 UI 实现。

后台主程序创建唯一协调器实例，并同时注入 HTTP 路由、礼物执行链和定时器执行链。

### 前端租约客户端

独立客户端负责：

- 创建会话。
- 周期续租和重试。
- 正常释放。
- 页面卸载时使用 keepalive/best-effort 释放。
- 将租约健康状态通知属性编辑器。

## 五、错误与安全处理

- 租约接口只允许同源请求，不接受跨源控制。
- 请求体使用严格大小上限和严格 JSON 字段集合。
- 属性 ID 必须对应当前存在的属性；会话令牌必须固定长度并使用安全随机数生成。
- 续租和释放必须同时匹配会话令牌与属性 ID，不能解除其他编辑页的租约。
- 过期租约在查询、创建或续租时惰性清理，避免额外常驻清理线程。
- 时间解析不接受宽松的 JavaScript 数字转换，避免 `1::2`、小数和尾随字符被误接收。
- 随机范围生成前验证整数和顺序，后端现有公式验证继续作为最终防线。

## 六、测试与验收

### 随机范围

- 构建负到正、全负、全正、零区间公式。
- 最低零保护和最大值限制。
- 识别旧随机增加、旧随机减少和新规范公式。
- 拒绝非整数和倒置范围。
- 小白模式只显示一个随机变化选项。

### 时间输入

- 三段、四段、超过 23 小时的三段格式。
- 分秒边界、四段小时边界、天数和安全整数上限。
- 空段、小数、负号、非数字、错误段数。
- 六个快捷按钮、减到零和非法草稿行为。
- 保存到配置后仍为正确总秒数。

### 编辑租约

- 创建、续租、释放、过期和非法令牌。
- 同属性多会话与不同属性隔离。
- 改名期间仍按稳定 ID 冻结。
- 冻结属性的礼物规则不改变值，其他属性仍变化。
- 礼物收据、贡献、盲盒和统计在冻结期间仍记录。
- 冻结属性的定时器跳过且不补算。
- 保存失败继续冻结；保存成功、取消、关闭和卸载释放。
- 续租失败显示警告并重试。
- Go 竞态测试验证协调器和规则执行并发安全。

### 完整门禁

- 相关前端单元与 DOM 回归测试。
- 前端全量测试、类型检查和 UI 构建。
- Go 相关测试、全量测试和竞态测试。
- UI 资源清单与 EXE 构建，确保新模块进入正式嵌入产物。

## 七、验收标准

1. 小白模式不再出现独立的随机增加和随机减少选项。
2. 用户可以用负数到正数定义一个随机变化范围，结果不低于零。
3. 旧随机规则打开后能正确显示为等价的新范围。
4. 时间属性可用三段或四段格式编辑，并通过按钮快速加减。
5. 编辑已有属性时，该属性不会被礼物或定时器规则改变，其他属性不受影响。
6. 退出编辑后规则只对新事件继续生效，不补算编辑期间的事件。
7. 页面异常退出不会造成永久冻结。
8. 完整前端、Go、竞态、UI 和 EXE 构建门禁全部通过。
