# Hosted 管理员系统重设计

## 状态

本设计于 2026-08-22 经用户逐页确认。它取代此前管理员体验设计中已经过时的 B 站管理员登录、七天会话、常驻近期 TOTP 状态、独立 OBS 页面和一次性邀请码展示方案。管理员认证继续遵循邮箱验证码方向，但采用本设计的轻量安全和三十天会话策略。

## 目标

管理员系统面向小规模、自用或少量运营人员，不按企业级云控制台设计。目标是让管理员进入页面后立即知道当前状态和下一步操作，并能用尽量少的页面完成账号、邀请码、OBS 和服务账号管理。

成功标准：

- 总览只展示状态、异常、待办和常用入口，不复制所有管理操作；
- 账号、房间、邀请额度和 OBS 在同一账号资源中管理；
- 邀请码为八位字母数字，可在有效期内持续查看和复制；
- 日常操作不要求 TOTP，少数可能导致管理员失去控制权的操作才临时验证；
- 管理员通过邮箱验证码登录，并在当前设备保持登录三十天；
- iOS Safari 可以稳定输入、自动填充和提交六位验证码，并对等待和失败给出明确反馈；
- 桌面界面紧凑，移动界面不横向溢出，不出现逐字换行。

## 产品原则

1. **任务优先，资源兜底。** 总览负责告诉管理员该处理什么；资源页负责完整查询和管理。
2. **一个对象只有一个主要入口。** OBS 属于主播账号，不再设置独立 OBS 导航；账号操作记录也跟随账号详情。
3. **渐进展开。** 创建表单、高级诊断和低频设置默认收起，需要时在当前上下文展开。
4. **安全与风险匹配。** 不用常驻安全状态和频繁验证打断日常工作，但仍保护会导致失去管理员控制权的操作。
5. **结果回到工作流。** 新邀请码直接进入列表，新账号变更直接更新详情；不把结果留在孤立的大卡片或仅显示一次的弹窗中。

## 视觉方向

使用中性运营控制台风格：浅灰画布、深海军蓝导航、信息蓝主操作。绿色、琥珀色和红色仅表示正常、警告和失败或破坏性操作。

- 桌面使用固定左侧导航和紧凑内容区；
- 内容卡片使用克制圆角、细边框和轻阴影；
- 表格优先于重复的大卡片；
- 主要按钮在每页标题区，次要操作使用描边按钮；
- 手机隐藏侧栏并使用菜单入口，表格只显示最关键字段，详情改为全宽面板；
- 所有可点击表头、按钮、输入框和菜单具有可见焦点；
- 动画遵循 `prefers-reduced-motion`。

## 信息架构

左侧导航只有五项：

1. **运营总览**
2. **主播账号**
3. **邀请码**
4. **B 站服务账号**
5. **系统设置**

操作记录不再占据独立导航。总览显示最近操作；账号详情显示该账号的变更；系统设置中的高级区域提供完整记录入口。

## 运营总览

总览包含四层信息：

- 服务可用状态和最近刷新时间；
- 启用账号、正常直播间、可用邀请码和凭据健康等少量核心指标；
- 按优先级排列的待办和异常，每项直接链接到拥有该问题的资源；
- 资源中心入口和最近操作。

总览允许一个高频主操作“创建邀请码”。它不得复制账号停用、额度修改、OBS 重签等详情页操作。无异常时显示简短空状态，而不是保留空白待办框。

## 主播账号

### 列表

主播账号使用紧凑表格，支持：

- 按账号 ID、显示名称、脱敏 UID 或房间号搜索；
- 按启用状态和“需要关注”筛选；
- 显示账号、直播间、邀请额度、最近活动和状态；
- 多选后批量启用、停用或调整邀请额度；
- 表头复选框同时负责全选和全部取消，不再提供重复的“清除选择”按钮。

批量工具条只在至少选择一个账号后出现。对于不适用于全部所选账号的动作，按钮应禁用并解释原因，不能对混合状态静默执行部分成功。

### 详情

桌面点击账号打开右侧详情抽屉；移动端进入全宽详情。详情集中展示：

- 启用状态、账号标识和创建时间；
- 当前直播间及修改入口；
- 邀请额度及调整入口；
- OBS 凭据状态、现有地址复制和最近签发时间；
- 重新签发 OBS；
- 与该账号相关的最近变更记录；
- 停用或重新启用账号。

重新签发 OBS 前显示目标账号和旧地址将失效的影响。它只需要确认，不要求 TOTP。成功后旧地址立即失效，新地址直接在账号详情中显示并可复制。

## 邀请码

### 数据和生命周期

- 新邀请码固定为八位大写字母和数字；字符集排除容易混淆的字符时，服务端和 UI 必须使用同一明确字符集；
- 创建时可以选择数量以及七天、三十天或永久有效；
- 有效邀请码持续显示完整代码，可复制或调用系统分享；
- 兑换、过期或手动作废后清除可恢复的完整代码，只保留末四位、状态、时间和关联账号；
- 邀请码兑换仍为一次性原子操作，过期或作废代码不可兑换。

为了支持有效期内再次查看，服务端除不可逆校验摘要外，还保存受服务器密钥保护的可恢复代码。列表接口只对已认证管理员返回仍有效的完整代码；普通兑换接口永不返回代码或密文。状态终结时应删除密文而不是只在 UI 脱敏。

### 页面

页面显示当前可用、本周已兑换和即将过期的简要统计，并支持按代码末尾或兑换账号搜索、按状态筛选。

“状态”和“创建时间”列支持排序：

- 创建时间默认最新优先，并可切换最早优先；
- 状态排序按可用、已兑换、已作废或过期分组，并可反向；
- 当前排序列和方向必须可见并通过 `aria-sort` 暴露；
- 排序可以与状态筛选和搜索组合。

右上角“创建邀请码”按钮展开紧凑面板，只包含数量和有效期。创建成功后面板自动收起，新代码插入列表顶部并短暂高亮，同时出现“已创建并复制”的可关闭提示。页面不再保留底部创建设置和创建结果大卡片。

## B 站服务账号

这是唯一的全局 B 站账号资源，页面只暴露管理员能采取行动的信息：

- 当前是否可用；
- 最近检测时间；
- 脱敏账号标识；
- 最近替换时间；
- 立即检测；
- 开始替换；
- 简短状态变化记录。

替换流程为：验证管理员 TOTP、提交新凭据、自动检测。旧凭据必须保留到新凭据检测成功，之后才原子替换。失败时继续使用旧凭据，并用非技术语言说明失败；底层 Cookie、完整 UID、响应正文和日志不得返回浏览器。

## 系统设置

系统设置分为常用区域和折叠的高级区域。

常用区域包含：

- 脱敏管理员邮箱和更换入口；
- 当前设备三十天会话说明；
- 退出其他设备；
- TOTP 是否已启用及重新设置；
- 恢复资料最近生成时间和重新生成；
- 退出当前登录。

高级区域包含完整操作记录、邮件发送状态和面向排障的系统诊断。默认不展开，不把原始服务器日志或敏感配置展示给浏览器。

## 轻量安全策略

### 会话

- 管理员邮箱验证码登录成功后签发三十天会话；
- Cookie 保持 `Secure`、`HttpOnly`、host-only、路径 `/` 和 `SameSite=Lax`；
- 浏览器不使用 `localStorage` 或 `sessionStorage` 保存管理员令牌、邮箱或验证码；
- 更换管理员邮箱、退出其他设备、凭据 epoch 变化或服务端撤销会使对应会话失效。

### TOTP

日常查看、邀请码、房间、额度、账号启停和 OBS 重签均不要求 TOTP。仅以下操作要求临时 TOTP：

1. 替换 B 站服务账号凭据；
2. 更换管理员邮箱；
3. 重新生成恢复资料。

重新设置 TOTP 本身要求当前 TOTP；丢失时走离线恢复。每次验证只授权当前已明确描述的目标操作，不显示或维护前端“安全会话剩余时间”，也不把验证扩展到其他操作。

确认弹窗必须写明目标和影响。普通失败不使管理员退出登录；管理员会话失效才返回登录页。

## 管理员登录

### 恢复会话

进入管理员路由先检查现有会话。页面最多显示三秒“正在恢复管理员会话”。

- 验证成功直接进入总览；
- 确认未登录显示邮箱登录；
- 三秒内未完成则显示可操作的登录卡片和“重新检查”入口，后台迟到结果不得覆盖用户已经开始的登录流程；
- 服务不可用必须显示服务错误，不能误判为未登录并静默发送邮件。

### 邮箱验证码

- 页面显示脱敏管理员邮箱和“发送验证码”；不要求输入完整邮箱；
- 验证码为六位数字，沿用服务端一次性、期限、失败次数和限流保护；
- 视觉为六格，但实现使用一个真实输入框；
- 输入框使用数字键盘提示和 `autocomplete="one-time-code"`；
- 支持逐位输入、整段粘贴、退格和 iOS Safari 系统自动填充；
- 有真实可见光标；
- 输入第六位后仅提交一次，不需要额外按钮；
- 成功后清空验证码状态并进入总览。

### 提交反馈

提交时锁定输入，六格进入禁用样式，并显示转圈和“正在验证验证码…”。转圈尊重减少动画偏好，并有等价的文本状态。

- 网络失败或超时：保留六位验证码，解除输入锁定，显示“网络连接失败，请检查网络后重试”，提供“重新验证”；
- 验证码错误、过期或已消费：清空输入，恢复焦点和光标，显示具体但不泄露管理员身份的提示，并提供重新发送入口；
- 限流：显示剩余等待时间并禁用重复发送；
- 页面销毁或导航后，迟到请求不得挂载界面或重复签发会话。

## 状态、错误和空状态

- 所有保存和检测操作都有进行中、成功和失败状态；
- 网络错误与业务拒绝分开处理，网络错误优先保留可重试输入；
- 表格加载失败保留筛选条件并提供重试；
- 空列表说明原因并提供唯一相关主操作；
- 批量操作返回逐项结果，任何部分失败都必须可见；
- 一次性展示的 OBS 新地址在关闭或离开详情时清除 DOM 中的临时值，但服务端仍按产品策略管理当前有效地址。

## 模块边界

前端拆分为以下职责清晰的模块：

- 管理员会话与邮箱登录状态机；
- 六位验证码输入与提交反馈组件；
- 管理员 Shell 和五项导航；
- 总览聚合视图；
- 账号列表、选择模型和账号详情；
- 邀请码列表、排序筛选和紧凑创建面板；
- B 站服务账号状态与原子替换流程；
- 系统设置与按操作触发的 TOTP 对话框；
- 通用通知、确认和网络重试组件。

后端提供面向页面的聚合读取接口，避免前端为了总览或账号详情串联大量请求。认证、邀请码状态、TOTP 授权和凭据替换仍由服务端决定，前端状态不能提升权限。

## 数据和 API 变化

预计需要追加而非修改已发布迁移：

- 管理员会话最大期限改为三十天；
- 邀请码增加八位展示后缀、可恢复密文、可选过期时间和终结时密文清除；
- 必要的服务账号检测时间和状态历史；
- 若现有审计数据不足，增加面向管理员的简化事件类型，不保存验证码、Cookie、完整凭据或恢复密码。

预计新增或扩展的管理员 API：

- 总览聚合；
- 账号分页、搜索、筛选、批量变更和账号详情；
- 当前 OBS 地址读取与重签；
- 邀请码分页、排序、筛选、批量创建和作废；
- 服务账号检测和原子替换；
- 管理员邮箱、会话撤销、TOTP 和恢复资料设置；
- 邮箱登录会话状态与明确错误分类。

所有列表必须服务端分页和排序，不能只排序当前浏览器页。API 使用稳定游标或明确页码，并返回总数或是否还有下一页。

## 可访问性和移动端

- 导航、排序、筛选、抽屉、弹窗和所有操作可用键盘完成；
- 表格排序通过按钮和 `aria-sort` 表达，不能只依赖箭头颜色；
- 状态变化通过礼貌 live region 宣布，轮询不反复播报；
- 移动菜单可关闭、可按 Escape 退出并恢复触发按钮焦点；
- 抽屉在移动端成为全宽页面或底部面板，禁止横向页面滚动；
- 六位验证码只有一个可访问标签和一个语义输入；
- 提交转圈具有文本替代，减少动画模式下可静止显示。

## 验证

### 后端

- 三十天会话、Cookie 属性、撤销和 epoch 失效；
- 邮箱验证码一次性消费、期限、失败次数、限流和错误分类；
- 八位邀请码字符集、唯一性、批量创建、三种有效期、排序筛选、原子兑换和终结时密文清除；
- 有效邀请码仅对管理员可恢复，普通兑换接口不可泄露；
- 账号搜索、筛选、分页和批量操作的完整或部分失败；
- OBS 重签无需 TOTP，但旧地址失效和新地址签发保持原子；
- 三类高风险操作要求操作级 TOTP，其他操作不要求；
- 服务账号新凭据验证成功才替换旧凭据。

### 前端

- 三秒会话恢复上限、重试和迟到结果隔离；
- iOS Safari 六格视觉、真实光标、自动填充、粘贴和单次自动提交；
- 提交转圈、网络失败保留、业务错误清空、重新验证和重新发送；
- 五项导航和移动菜单；
- 账号列表、详情、批量工具条和无重复清除入口；
- OBS 合并进账号详情；
- 邀请码紧凑创建、结果插入、复制分享、筛选和服务端排序；
- 服务账号状态、检测和替换；
- 系统设置高级区域默认折叠；
- 桌面和手机浏览器截图回归，无逐字换行或横向溢出。

完成前运行聚焦 Go 和 Vitest、完整 Go 测试与相关 race、完整 Vitest、TypeScript 类型检查、Hosted 构建，并在真实生产资源路径上做桌面和 iOS Safari 冒烟。

## 非目标和集成边界

- 不改变普通主播的 B 站登录流程；
- 不改变 OBS 公共认证协议本身，只改变管理员管理入口；
- 不引入密码、短信或第三方 OAuth 管理员登录；
- 不建设角色权限、团队成员、审批流或企业级安全中心；
- 不把原始技术日志、Cookie、验证码、恢复密码或完整管理员邮箱暴露给浏览器；
- 不改变大陆更新镜像、COS 更新分发、GitHub 发布流程或桌面版更新机制；
- 不在本设计任务中合并 `master`、推送、部署或修改 Hosted 之外的代码。
