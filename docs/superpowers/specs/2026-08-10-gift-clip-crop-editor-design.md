# 礼物动画剪裁编辑器设计

## 目标

将礼物动画回放的“拖动画面微调”改为类似图片剪裁的编辑方式。用户在生成视频前，通过一个带 8 个控制点的剪裁框选择动画区域；最终视频的宽高与剪裁区域在原始素材中的像素尺寸完全一致。同一动画的剪裁设置持久保存，后续只需调整一次。

## 范围

本功能继续支持现有 GIF、WebP 和完整礼物特效素材，不改变送礼记录、媒体代理、头像获取、MP4/WebM 能力检测或文件下载机制。

本次不增加旋转、翻转、固定宽高比、缩放输出分辨率、手动输入坐标或信息条独立编辑功能。

## 编辑器结构

编辑区域按动画实际画面的原始宽高比显示完整素材，不再固定为 480×480。Canvas 负责循环播放动画，DOM 控制层覆盖在 Canvas 上方，负责剪裁遮罩、剪裁边框、8 个控制点和底部信息条占位预览。

剪裁框默认覆盖完整素材。框外区域使用半透明暗色遮罩；框内区域保持正常亮度。控制点分布为四角、四边中点：

- 拖动框内空白区域会整体移动剪裁框。
- 左、右控制点只调整宽度。
- 上、下控制点只调整高度。
- 四角控制点同时调整宽度和高度，宽高比自由变化。
- 所有移动和缩放均使用 Pointer Events 和指针捕获，兼容鼠标与触摸。
- 剪裁框始终限制在素材范围内。
- 剪裁框在原始素材坐标中的宽和高均不得小于 64px。

“恢复全部画面”会把剪裁框恢复为素材完整范围。“确定剪裁并生成”会保存剪裁数据并进入录制流程。直接关闭弹窗不会覆盖上一次已确认设置。

## 素材尺寸门槛

素材完成解码后，以实际可渲染画面尺寸为准进行检查。宽度或高度任一小于 64px 时，不显示剪裁编辑器，也不启动 Canvas 捕获或 MediaRecorder；弹窗显示“动画尺寸过小，无法制作回放”并保留关闭入口。

GIF 和 WebP 使用其实际图像画布尺寸。完整礼物特效使用 RGB 与 Alpha 合成后的实际画面尺寸，不使用包含双通道的打包视频尺寸，也不再预先缩小到 480px。

送礼记录列表阶段通常没有可靠的动画尺寸，因此列表仍显示“制作回放”。尺寸门槛在素材读取和解码后立即执行。

## 数据模型与持久化

使用归一化剪裁数据保存设置：

```ts
interface GiftClipCrop {
  x: number;
  y: number;
  width: number;
  height: number;
}
```

四个值均相对于原始素材尺寸，范围为 0–1。默认值为 `{ x: 0, y: 0, width: 1, height: 1 }`。

设置保存在 `settings.giftClipCrops: Record<string, GiftClipCrop>`。动画标识继续沿用现有规则：完整特效优先使用 effect ID；短动画使用去除查询参数后的素材 URL 哈希；无法获得素材 URL 时回退到礼物 ID。最多保存 200 个动画剪裁预设；超过上限时裁减到 200 条，不承诺具体淘汰顺序。

前后端都会校验有限数值、0–1 范围、正宽高和素材边界。加载剪裁设置后，再根据当前素材像素尺寸应用 64×64 最小范围；能够修复的越界数据会收缩或平移回素材内部，无法修复的数据恢复为完整素材。

现有 `giftClipPlacements` 平移数据不再使用，也不尝试近似迁移，因为旧的平移和补偿放大无法在没有素材尺寸时无损换算为剪裁区域。升级后同一动画首次打开时使用完整素材。Go 配置分片格式版本从 10 升至 11，防止旧程序静默丢弃新的剪裁字段。

## 坐标换算与成片尺寸

编辑器显示尺寸只影响交互，不影响保存结果。DOM 剪裁框的位置先换算到素材显示区域，再保存为归一化坐标。

生成时按当前实际素材尺寸换算原始像素区域：

```text
sourceX = round(crop.x * sourceWidth)
sourceY = round(crop.y * sourceHeight)
outputWidth = round(crop.width * sourceWidth)
outputHeight = round(crop.height * sourceHeight)
```

四个结果会再次限制到素材边界，并保证输出宽高至少为 64px。输出 Canvas 的像素宽高直接设置为 `outputWidth × outputHeight`，不固定为 480×480，也不设置最长边上限。

每一帧使用 Canvas `drawImage` 的源区域参数，把剪裁区域按相同像素尺寸绘制到输出 Canvas：

```text
drawImage(source, sourceX, sourceY, outputWidth, outputHeight,
          0, 0, outputWidth, outputHeight)
```

因此动画不会被拉伸，剪裁框的宽高和最终视频宽高完全一致。

## 信息条预览与渲染

头像、昵称和“赠送 礼物 × 数量”信息条固定在剪裁区域底部。编辑阶段由剪裁框内部的不可交互 DOM 占位层预览；录制阶段由 Canvas 绘制。成片继续不显示 UID。

信息条所有尺寸只按照剪裁区域宽度缩放，不考虑剪裁高度：

```text
overlayScale = outputWidth / 480
```

信息条高度、底部边距、左右边距、圆角、头像尺寸、字体大小和内部间距都使用现有 480px 设计值乘以 `overlayScale`。较矮的剪裁区域中，信息条可以占据较大的画面比例，不进行基于高度的二次缩小。信息条继续使用现有半透明紫粉渐变，不完全遮挡动画。

## 状态流程

1. 打开弹窗，显示素材读取状态。
2. 解码素材并检查实际尺寸。
3. 尺寸合格时进入剪裁编辑状态，循环播放动画。
4. 用户移动或缩放剪裁框，并通过信息条占位层检查最终构图。
5. 用户点击“确定剪裁并生成”，剪裁数据立即保存。
6. 编辑控件隐藏，创建与剪裁区域像素尺寸一致的输出 Canvas 和录制流。
7. 按现有格式探测顺序优先生成 MP4，不支持时回退 WebM。
8. 生成完成后显示循环视频预览、“重新剪裁”和“保存 MP4/WebM”。
9. “重新剪裁”重新载入当前已确认剪裁框；再次确认后覆盖同一动画的预设。

## 错误处理与资源释放

- 素材读取或解码失败时显示现有可操作错误并提供重试。
- 素材宽或高小于 64px 时显示明确尺寸错误，不提供生成按钮。
- 无效持久化数据恢复为完整素材，不阻断用户制作回放。
- 录制失败时保留“重新剪裁/重试”入口。
- 关闭弹窗、重新剪裁或发生错误时，继续释放 RAF、MediaRecorder 流、媒体元素、Blob URL 和临时 Canvas 资源。

## 模块边界

`gift-clip-studio.ts` 继续作为深模块，负责动画标识、剪裁几何、DOM 交互、帧绘制、录制和资源释放。纯几何函数独立导出，供 Vitest 直接验证。

配置页只负责按动画标识读取初始剪裁数据，并通过确认回调更新 `settings.giftClipCrops`。存储层和 Go 后端负责格式归一化、数量限制与分片版本，不参与编辑器交互。

## 验证标准

### TypeScript 单元测试

- 默认完整剪裁区域。
- 框体移动在四个方向都不能越过素材边界。
- 8 个控制点分别改变正确的边，并遵守 64×64 最小尺寸。
- 归一化数据与原始像素区域双向换算正确。
- 输出 Canvas 像素尺寸与剪裁区域一致。
- 信息条仅按剪裁宽度缩放。
- 宽或高小于 64px 时拒绝进入录制。
- 同一动画标识复用剪裁数据，损坏数据恢复完整素材。

### Go 测试

- `giftClipCrops` 配置可以写入、读取和克隆。
- 非有限数值、越界数据、空键和超过 200 条的配置被归一化。
- 配置分片版本 10 可以升级到 11，新于 11 的配置继续拒绝加载。

- 关闭并重新打开同一动画时复用剪裁框。
